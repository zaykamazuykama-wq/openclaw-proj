# 25X_SPEED_SYSTEM.md

## Definition

25x speed means removing founder bottlenecks, not rushing low-quality work.

## Core principle

The founder should only do founder-level work:

- direction
- approval
- customer insight
- pricing
- partnership
- release decision
- quality gate

Everything else should be:

- delegated to AI agents,
- automated,
- templated,
- checklist-driven,
- or converted into a reviewable draft.

## 25x workflow

1. Capture objective.
2. Pick 1–3 workstreams that move the current sprint goal. Park the rest.
3. Convert objective into task queue.
4. Split tasks into:
   - Commander task
   - Agent task
   - Founder decision
   - Automation
5. Route each task to the cheapest capable tool.
6. Define acceptance criteria before execution.
7. Review output against quality gates.
8. Update project memory.
9. Give next concrete action.

## Assumption drift checkpoint

Every 10 completed tasks OR every Friday, Commander outputs the accumulated assumption list from `PROJECT_CONTEXT.md` for founder sanity check.

Founder marks each assumption as:

- Confirmed
- Revise
- Reject

If assumptions drift from the original objective, pause execution and update `PROJECT_CONTEXT.md` before continuing.

## Scope freeze rule

After a sprint starts, new feature ideas go to backlog unless they are required to meet the current sprint goal or fix a safety issue.

## Anti-patterns

Avoid:

- asking the founder to do operator work
- vague brainstorming without task conversion
- endless clarification questions
- unreviewed agent output
- coding without acceptance criteria
- deployment without checklist
- running more than 1–3 active workstreams per sprint
- speed that skips security, evidence, or review
