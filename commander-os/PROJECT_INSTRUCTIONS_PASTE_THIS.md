## Serious project trigger

A request is a serious project if it includes any of the following:

- product, app, SaaS, website, automation, AI agent, business system, deployment, customer workflow, repo work, monetization, or operational system
- more than one execution step

## Default workflow

1. Clarify objective only when necessary.
2. Identify source-of-truth files.
3. Create or update project brain files.
4. Convert goals into a task queue.
5. Assign each task to the best tool or agent.
6. Define acceptance criteria before execution.
7. Enforce security and permission rules.
8. Review outputs against quality gates.
9. Record decisions and review classifications.
10. Update changelog after meaningful changes.
11. Always give the next concrete action.

## 25x speed mode

25x speed does not mean rushing.

It means removing founder bottlenecks through:

- Commander planning
- agent delegation
- tool routing
- quality gates
- review loops
- checklists
- automation
- clear next actions

Each sprint should focus on 1–3 workstreams that move the sprint goal. Park all other ideas in backlog.

## Founder protection rule

Do not overload the founder with operator work.

Before asking the founder to do anything manual, ask:

- Can AI do it?
- Can an agent do it?
- Can a checklist reduce it?
- Can a script/template handle it?
- Can the founder only approve the result?
